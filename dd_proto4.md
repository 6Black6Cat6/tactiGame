# Прототип: пошаговая стратегия (Godot)

## 1. ОПИСАНИЕ МЕХАНИКИ (ЯДРО)

### 1.1. Ход
| Элемент               | Описание                                                     |
|-----------------------|--------------------------------------------------------------|
| Ручное переключение   | Игрок(и) вручную запускает фазу симуляции после планирования |
| Фаза планирования     | Игрок(и) дают приказы своим юнитам                           |
| Фаза симуляции        | Система выполняет расчет приказов и физики                   |
| Отсутствие прерываний | Во время симуляции управление невозможно                     |

### 1.2. Понятия приказа и действия
Приказ - это указания игрока для юнита.
Действие - это минимальные действия юнита.
И приказы, и действия подразделяются на одинаковые типы: Движение, Вращение, Активность.
Типы обрабатываются абсолютно независимо. Т.е. можно назначить одновременно приказы движения, вращения и активности. Изменение действия любого типа не прервет и не изменит действие другого типа.

### 1.3. Приказы
| Тип        | Приказ      |                                                       |
|------------|-------------|-------------------------------------------------------|
| Движение   | Перемещение | Перемещение в точку назначения                        |
| Вращение   | Повернуться | Повернуться в указанном направлении (фиксированный азимут) |
| Вращение   | Смотреть    | Поворачиваться к указанной точке вне зависимости от положения |
| Активность | Выстрел     | Выполняется выстрел в текущем направлении |
| Активность | Атака       | Иное название "Атака по возможности", Выстрел выполняется только при наличии противника в зоне поражения |

Приказы назначаются игроком на timeline во время фазы планирования. Длительность приказов, имеющих скорость (например, Перемещение) вычисляется исходя из нее. Длительность некоторых приказов имеет фиксированное значение (например, Выстрел). Для приказов, длительность которых не может быть вычислена заранее (например, Атака), длительность назначается игроком.
Приказы разных типов могут быть назначены на один и тот же период времени. Например, "Перемещение + Атака" означает, что юнит должен двигаться и при обнаружении противника выстрелить без остановки. Несмотря на то, что приказы одного типа не отменяют приказы другого типа, в будущем необходимо предусмотреть их влияние. Например, перемещение не позволит юниту отвернуться более чем на 45 градусов от направления перемещения, при перемещении увеличивается разброс оружия и т.п.
Выполняемые приказы могут быть прерваны на новом ходу игроком, т.е. игрок может удалить остаток приказа и дать другой.

### 1.4. Действия
| Тип        | Действие    | Прерываемо | Описание                                         |
|------------|-------------|------------|--------------------------------------------------|
| Движение   | Перемещение | Да         | Движение в точку назначения, время выполнения рассчитывается как скорость на расстояние |
| Вращение   | Поворот     | Да         | Повернуться в указанном направлении (фиксированный азимут) |
| Вращение   | Смотреть    | Да         | Поворачиваться к указанной точке вне зависимости от положения |
| Активность | Обнаружение | Да         | Лучом проверяется видимость юнита в течение времени реакции, только после этого юнит считается "обнаруженным" - определяется его принадлежность к команде и расстояние до него |
| Активность | Выстрел     | Нет        | Выполняется ожидание на время реакции (нажатие на спуск), потом мгновенный выстрел в случайном направлении в пределах конуса разброса оружия, проверка попадания физическим лучом |

Действия также выстраиваются на timeline. Но во время фазы симуляции. Некоторые действия могут быть просчитаны в момент запуска фазы симуляции т.к. они полностью соответствуют приказу - например, движение. А некоторые появляются в процессе симуляции - например, приказ Атака выполняется как набор из нескольких действий: Обнаружение, Выстрел, Смотреть.
1. При появлении юнита в конусе видимости
1.1 timeline в пределах этого приказа очищается от всех запланированных Выстрелов.
1.2 после текущего выполняемого действия в план добавляется Обнаружение, все, ранее поставленные, Обнаружения сдвигаются на более поздний срок.
2. после завершения всех действий в рамках этого приказа на timeline ставятся Смотреть на ближайшего из врагов, а потом Выстрел в него.

Разумеется любое действие прерывается смертью юнита, его выполняющего. Но изменением приказа не все действия могут быть прерваны (например, Выстрел - если начал нажимать спуск, то уже не остановится).
Обнаружение также прерывается потерей прямой видимости (препятствие заслонило) или выходе обнаруживаемого юнита из конуса видимости.
Если ранее обнаруженный юнит пропал из поля зрения, то его обнаружение должно произойти повторно.

## 2. Интерфейс
### 2.1. Фаза планирования
В нижней части экрана должен находится timeline с настроенными приказами для выбранного юнита.
Время слева-направо, должны быть отмечены границы ходов.
Длительные приказы могут выходить за пределы одного хода, они продолжат выполнение, если игрок его не удалит.
Также timeline разделен по вертикали на типы приказов, для обеспечения параллельности настройки. 
Таким образом, кроме настройки приказа на карте игрок может изменять их длительность.
На timeline также должен быть бегунок для предпросмотра положений своих юнитов в каждый период времени.
При этом коллизии не рассчитываются, т.е. игрок просто должен увидеть наложение юнитов.
На редактирование приказов это никакого влияния не имеет, в будущем предусмотреть изменение приказа с этого момента.
Также игрок не видит юниты противника, которые не видны (не в конусе видимости) его юнитам.
Приказы других игроков, в том числе и ИИ - не видны.

### 2.2. Действия на timeline (только при активном юните)

| Действие                           | Описание                                     |
|------------------------------------|----------------------------------------------|
| Выбор приказа                      | Левый клик по плашке приказа                 |
| Создание нового с текущего момента | Левый клик по пустой части timeline          |
| Изменить длительность              | "Зацепить и потянуть" за край плашки приказа |
| Удалить приказ                     | Delete при выделенном                        |
| Масштаб                            | Ctrl + колесико на timeline                  |
| Перемещение "окна видимости"       | Колесико                                     |
| Запуск фазы симуляции              | Кнопка "Start Turn" или пробел               |

### 2.3. Действия на карте

| Действие         | Описание                                                                   |
|------------------|----------------------------------------------------------------------------|
| Выбор юнита      | Левый клик по юниту                                                        |
| Перемещение      | Правый клик на точку                                                       |
| Поворот          | Ctrl + Правый клик - выбор направления обзора                              |
| Смотреть         | Ctrl + Shift + Правый клик - выбор точки цели приказа                      |
| Запуск симуляции | Кнопка "Start Turn" или пробел                                             |

### 2.4. Фаза симуляции
Проигрывается как мультик - происходит одновременное выполнение всеми юнитами данных им приказов.
В этой фазе игрок не может ни на что уже повлиять юниты живут исходя из решений принятых на фазе планирования.

FF - возможен при промахе, при смерти атакуемого юнита (друг стоял дальше), при назначении приказа Атака в направлении своего юнита. 
При этом стрельба по своим самим юнитом "осознанно" не производится.

## 4. Дополнительные постулаты для прототипа

Для прототипа предлагается использовать режим без ИИ с двумя последовательными фазами планирования для двух команд.

Условие победы - уничтожение противника.

Карта - по размерам окна.

Юниты разместить по краям карты напротив друг-друга.
