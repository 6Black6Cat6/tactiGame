# Прототип: пошаговая стратегия с рекомендациями (Godot)

## 1. ОПИСАНИЕ МЕХАНИКИ (ЯДРО)

### 1.1. Ход
| Элемент | Описание |
|---------|----------|
| Ручное переключение | Игрок вручную запускает фазу симуляции после планирования |
| Фаза планирования | Игроки дают приказы своим юнитам |
| Фаза симуляции | Система выполняет действия |
| Отсутствие прерываний | Во время симуляции управление невозможно |

### 1.2. Планирование
| Тип | Выполнение |
|-----|------------|
| Приказ | Выполняется всегда |
| Рекомендация | Выполняется только при вероятности успеха  0.7 |
| Порог | Глобальный: 0.7 |
| Отсутствие указаний | Юнит действует по ИИ (преследование ближайшего врага) |

### 1.3. Юнит
| Компонент | Параметры |
|-----------|-----------|
| Тело | Позиция, скорость, радиус коллайдера 20px |
| Оружие | Дальность, конус разброса, урон |

### 1.4. Сенсорика
| Элемент | Описание |
|---------|----------|
| Видимость | Конус 120°, дальность R |
| Обнаружение | Прямая линия без препятствий (луч physics ray) |
| Физический луч | Использует `PhysicsRayQueryParameters2D` для проверки видимости и попаданий |

### 1.5. Действия
| Действие | Описание |
|----------|-----------|
| Перемещение | Вектор / точка назначения |
| Атака | Выстрел в случайном направлении в пределах конуса разброса оружия, проверка попадания физическим лучом |

### 1.6. ИИ по умолчанию
| Поведение | Описание |
|-----------|----------|
| Преследование | Двигаться к ближайшему видимому врагу, стрелять при возможности |

### 1.7. Приоритет
| Правило | Описание |
|---------|----------|
| Рекомендации важнее | Если игрок дал рекомендацию — она выполняется при соблюдении условий (порог 0.7), иначе юнит действует по ИИ |

### 1.8. Окружение
| Элемент | Описание |
|---------|----------|
| Карта | Плоскость без препятствий |
| Границы | Непроходимые края |

### 1.9. Интерфейс
| Действие | Описание |
|----------|-----------|
| Выбор юнита | Левый клик |
| Рекомендация | Правый клик (на точку — перемещение, на врага — атака) |
| Приказ | Shift + Правый клик (на точку — перемещение, на врага — атака) |
| Запуск симуляции | Кнопка "Start Turn" или пробел |

### 1.10. Визуализация
| Элемент | Описание |
|---------|----------|
| Планирование | Линии перемещения, маркеры атаки (разный цвет: рекомендация — синий, приказ — красный) |
| Прогноз | Вероятность попадания при наведении на цель (только для рекомендаций) |
| Симуляция | Проигрывание хода с анимацией движения и выстрелов |

## 3. ПРОМТ ДЛЯ ПРОТОТИПА В GODOT

Создай прототип в Godot 4 по следующему ТЗ:

### 3.1. Сцена и узлы

- **Main** (Node2D)
  - **Units** (Node2D) — контейнер для юнитов
  - **UI** (Control) — панель с кнопками и информацией
  - **GameController** (Node) — управление ходами и логикой

### 3.2. Скрипты

#### Unit.gd (прикреплён к сцене юнита)
- Экспортируемые параметры:
  - `speed: float = 200.0`
  - `weapon_range: float = 400.0`
  - `weapon_spread: float = 20.0` (градусов, полный разброс)
  - `damage: int = 1`
  - `is_player: bool = true`
  - `max_health: int = 3`
- Переменные:
  - `current_health: int`
  - `direction: Vector2` — направление взгляда
  - `planned_action: Dictionary` (тип, цель, является_приказом)
- Методы:
  - `_ready()` — инициализация
  - `_process(delta)` — движение во время симуляции
  - `plan_move(target_pos: Vector2, is_order: bool)`
  - `plan_attack(target_unit: Unit, is_order: bool)`
  - `execute_plan()` — выполнение запланированного действия
  - `shoot(target: Unit)` — выстрел с физическим лучом
  - `get_visible_enemies()` — возвращает массив видимых врагов (конус 120°, луч)
  - `get_hit_probability(target: Unit)` — вероятность попадания для отображения
  - `take_damage(amount: int)` — получение урона
  - `die()` — удаление юнита

**Важные детали реализации:**
- У юнита есть `CollisionShape2D` для физических взаимодействий
- Для стрельбы используется `PhysicsRayQueryParameters2D`:
  ```gdscript
  var spread_angle = randf_range(-weapon_spread / 2, weapon_spread / 2)
  var bullet_direction = direction.rotated(deg_to_rad(spread_angle))
  var query = PhysicsRayQueryParameters2D.create(
      global_position,
      global_position + bullet_direction * weapon_range
  )
  query.collision_mask = 1
  query.exclude = [self]
  var result = get_world_2d().direct_space_state.intersect_ray(query)

Для видимости используется такой же луч без препятствий
Вероятность попадания рассчитывается как 1.0 - (отклонение / (weapon_spread/2))
Умерший юнит удаляется через queue_free(), проверка is_alive не требуется

#### GameController.gd
Переменные:
planning_phase: bool = true
player_units: Array[Unit]
enemy_units: Array[Unit]
Методы:
start_planning_phase() — очистка планов, включение ввода
start_simulation_phase() — вызов execute_plan() у всех юнитов
end_simulation_phase() — окончание симуляции, проверка победителя
check_winner() — проверка условий победы
Важные детали:
Нет автоматического таймера — фаза планирования длится сколько угодно
Игрок нажимает кнопку "Start Turn" для перехода к симуляции
Симуляция длится фиксированное время (3 секунды) с анимацией

#### InputHandler.gd (или в Main)
Обработка кликов:
Левый клик — выбор юнита (подсветка)
Правый клик:
Если выбран юнит и клик на враге — unit.plan_attack(enemy, false)
Если выбран юнит и клик на пустом месте — unit.plan_move(click_pos, false)
Shift + Правый клик:
Если выбран юнит и клик на враге — unit.plan_attack(enemy, true)
Если выбран юнит и клик на пустом месте — unit.plan_move(click_pos, true)
Визуализация:
При планировании рисовать линию от юнита до цели (синяя — рекомендация, красная — приказ)
При наведении на врага показывать процент попадания (если выбран свой юнит)
AI.gd (можно встроить в Unit для врагов)
В фазу планирования для врагов:
Найти ближайшего видимого игрока через get_visible_enemies()
Если видит и в пределах дальности — plan_attack(target, false)
Если видит, но вне дальности — plan_move(target.position, false)
Если не видит — стоять на месте

### 3.3. Визуальные элементы (примитивы для прототипа)
Юниты — круги (свои — синие, враги — красные) с CollisionShape2D
Конус видимости — отображать при выборе юнита (сектор 120°)
Линии планирования — во время фазы планирования (Line2D)
Прогноз попадания — текст рядом с мышью или в UI
Эффекты попадания/промаха — временные Label

### 3.4. Требования к прототипу
Рабочий цикл: планирование (без таймера)  кнопка запуска  симуляция (3 сек)  планирование
Рекомендация не выполняется, если вероятность попадания < 0.7 (атака не происходит, юнит следует ИИ)
Приказ выполняется всегда
Враги управляются простым ИИ (преследование)
После смерти юнит удаляется со сцены (queue_free)
Победа, когда все юниты противника уничтожены
Для проверки попадания используется физический луч с учётом коллайдеров

## 4. ПРИМЕЧАНИЯ ДЛЯ РАЗРАБОТЧИКА
### 4.1. Стрельба и баллистика
Разброс оружия (weapon_spread) — полный угол, в пределах которого может отклониться пуля
Пуля летит по направлению: direction + случайное отклонение
Попадание проверяется физическим лучом: intersect_ray() определяет, какой юнит находится на пути пули
Дружественный огонь возможен, если луч попадает в другого юнита до цели

### 4.2. Вероятность попадания
Рассчитывается как 1.0 - (угол_отклонения / (weapon_spread/2))
Угол отклонения — угол между направлением юнита и направлением на цель
Если цель вне конуса оружия — вероятность 0%

### 4.3. Видимость
Используется PhysicsRayQueryParameters2D для проверки препятствий
Учитывается угол (конус 120°) и дистанция
Для прототипа препятствий нет, но луч готов к их появлению

### 4.4. Управление ходами
Нет автоматического таймера на фазу планирования
Игрок нажимает кнопку или пробел для запуска симуляции
Во время симуляции (3 секунды) ввод заблокирован
После симуляции автоматически начинается фаза планирования

### 4.5. Физические слои
Слой 1: юниты (CollisionShape2D)
В Project Settings  Layer Names  Physics Layer 1 назвать "units"

### 4.6. Оптимизация
Умершие юниты удаляются, проверки is_alive не нужны
Ссылки на мёртвых юнитов не сохраняются в планах
Для визуальных эффектов используются временные ноды с автоматическим удалением
