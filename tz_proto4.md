# Техническое задание (Godot 4)

Постановка для реализации прототипа; прикладная механика совпадает с `dd_proto4.md`.

**Приказ** — указание игрока юниту. **Действие** — минимальная единица выполнения на timeline. Верхний уровень независимости — **два типа**: **движение** и **активность**; изменение выполнения в одном типе не прерывает и не подменяет выполнение в другом. Приказы «смотреть», «атака», «атака по возможности» и связанные действия (поворот, обнаружение, атака) относятся к **активности**; «перемещение» — к **движению**. Приказы разных типов могут перекрываться по времени.

## 2. Конфиг (game_config.tres)

Параметры по умолчанию:

- `units_per_side` = 5 — количество юнитов на сторону
- `reaction_min` = 300, `reaction_max` = 1500 — диапазон реакции (мс)
- `view_distance` = 500 — дальность видимости (пиксели)
- `view_cone` = 120 — конус видимости (градусы)
- `weapon_range` = 400 — дальность стрельбы (пиксели)
- `weapon_spread` = 20 — конус разброса оружия (градусы)
- `move_speed_min` = 100, `move_speed_max` = 500 — скорость движения (пикс/сек)
- `rotate_speed_min` = 60, `rotate_speed_max` = 120 — скорость поворота (град/сек)
- `unit_size` = 20 — радиус юнита (пиксели)
- `turn_duration` = 5000 — длительность хода (мс)

## 3. Сцена unit.tscn

- `Node2D` (корень)
- `Sprite2D`
- `CollisionShape2D` (круг, радиус из конфига)
- скрипт: `unit.gd`

Компоненты юнита: **тело** (позиция, скорость и скорость поворота из диапазонов конфига, размер, реакция), **оружие** (ссылка на ресурс: дальность, конус разброса, урон, физический луч), **видимость** (конус и дальность R из конфига).

## 4. unit.gd — параметры

Состояния симуляции (действия на уровне кода можно отражать перечислением, не смешивая с типами приказов):

- `StateType`: условно `MOVE`, `ROTATE`, `DETECTION`, `ATTACK` и т.п. по необходимости симулятора

Два **трека timeline** (типы приказов по вертикали UI):

- `Track`: `MOVEMENT` (движение), `ACTIVITY` (активность; здесь же приказ «смотреть» и цепочки атаки)

Поля:

- `reaction_time` — при спавне случайно в `[reaction_min; reaction_max]` из конфига
- `move_speed` — при спавне случайно в `[move_speed_min; move_speed_max]`
- `rotate_speed` — при спавне случайно в `[rotate_speed_min; rotate_speed_max]` (град/сек)
- `weapon` — ссылка на `weapon.tres`
- `position: Vector2`, `direction: Vector2` — направление обзора / оружия
- `team_id: int` (0 — игрок, 1 — противник)

## 5. Ресурс order.gd

**Типы приказов:**

- `OrderType`: `MOVE` (перемещение), `WATCH` (смотреть — поворот в направлении), `ATTACK` (безусловная атака), `ATTACK_IF_POSSIBLE` (атака по возможности)

- `track: Track` — `MOVEMENT` или `ACTIVITY`; `WATCH`, `ATTACK`, `ATTACK_IF_POSSIBLE` всегда на `ACTIVITY`

- `start_time: int`, `duration: int`  
  Длительность: для приказов со скоростью (перемещение) — из скорости и расстояния; для части приказов — фикс (атака); для приказов без заранее вычислимой длительности (атака по возможности) — задаётся игроком на timeline.

- `target_position: Vector2` — для `MOVE`
- `target_direction: Vector2` — для `WATCH` и при необходимости для атакующих приказов (направление по умолчанию до уточнения симулятором)

**Прерываемость:**
Понятие подразумевает, что если данный приказ переходит через границу хода, то остаток может быть отменен игроком. Так как это понятие применимо к действиям, то важно учитывать на каком именно действии приказ перешёл через границу хода.
Прерываемы: перемещение, поворот, обнаружение.
Не прерываемо: атака.

### 5.1. Действия симуляции (отдельно от приказов)

Действия — записи на timeline **в фазе симуляции** (часть генерируется при старте симуляции из приказов, часть — в процессе). Удобно вынести в тип `Action` / `action.gd` (или эквивалент): общие поля **`track`**, **`start_time`**, **`duration`**, **`interruptible`**, опционально **`parent_order_id`** / ссылка на приказ для правил вроде очистки «атак» внутри одного `ATTACK_IF_POSSIBLE`.

| Тип действия (`ActionType`) | Трек | Поля (payload) | Длительность |
|-----------------------------|------|----------------|--------------|
| **Перемещение** | `MOVEMENT` | `target: Vector2` — точка назначения | длительность из расстояния от позиции юнита на начало действия до `target` и `move_speed` |
| **Поворот** | `ACTIVITY` | `facing: Vector2` — куда развернуть взгляд / ось конуса оружия | из угла поворота от текущего `direction` к `facing` и `rotate_speed` |
| **Обнаружение** | `ACTIVITY` | `subject_unit_id: int` — кого проверяют; по успеху: команда и расстояние до субъекта | `reaction_time` исполнителя |
| **Атака** | `ACTIVITY` | — | ожидание `reaction_time`, затем выстрел |

Правила заполнения из приказов:

- **Приказ `MOVE`** → одно или несколько действий **Перемещение** (в прототипе достаточно одного на весь сегмент; при дроблении по ходам — хвост как новое действие с тем же `target`).
- **Приказ `WATCH`** → **Поворот** с `facing = target_direction` приказа.
- **Приказ `ATTACK`**: при заданном в приказе `target_direction` — сначала **Поворот** (`facing`), затем **Атака**; иначе сразу **Атака**.
- **Приказ `ATTACK_IF_POSSIBLE`**: окно на timeline задаёт игрок; внутри симулятор наполняет **Обнаружение** / **Поворот** / **Атака** по п. 7.2.

## 6. Модель таймлайна (timeline.gd)

- `orders: Array[Order]` — только приказы, редактируемые в фазе планирования
- очередь действий (`Array[Action]` или эквивалент) — ведётся симулятором на время фазы симуляции; можно держать в `simulator.gd` или расширить модель timeline — на усмотрение, важно единое время и привязка к `MOVEMENT` / `ACTIVITY`
- `turn_duration: int` из конфига
- позиция просмотра / масштаб для UI

Две независимые дорожки по типам приказов; на UI — параллельная настройка по вертикали.

Методы:

- `add_order(order, track, start_time)`
- `resize_order(order, new_duration)` — изменение длительности «захватом» края плашки
- `remove_order(order)` — в т.ч. удаление остатка приказа на новом ходе
- `get_orders_at_time(time, track)`

Длинные приказы могут выходить за границу одного хода; за пределами текущего хода плашки отображаются полупрозрачными.

## 7. Simulator (simulator.gd)

Вход: список юнитов, их timeline, момент начала хода.

**Фазы:** на фазе планирования игрок задаёт приказы; **ручное** переключение на фазу симуляции (кнопка / пробел). Во время симуляции управление отсутствует; проигрывание — одновременное выполнение приказами всех юнитов («как мультик»).

Действия ведутся на timeline **в фазе симуляции**. Часть из них (в т.ч. **перемещение**) может быть просчитана при **запуске** фазы симуляции; часть появляется **в процессе** симуляции. Приказ «атака по возможности» реализуется как набор действий **обнаружение** и **атака**.

### 7.1. Приказ «Атака» (`ATTACK`)

Действие **Атака**:
0. TO THINK: Может быть в приказе указывать направление, а тогда здесь должно появиться действие **поворот**.
1. Ожидание на время реакции (нажатие на спуск).
2. Мгновенный выстрел: случайное направление в пределах конуса разброса оружия; проверка попадания **физическим лучом**.

### 7.2. Приказ «Атака по возможности» (`ATTACK_IF_POSSIBLE`)

При появлении юнита в **конусе видимости**:

1. В пределах этого приказа timeline очищается от всех запланированных действий **атака**.
2. После текущего **незавершённого** действия в очередь вставляется **обнаружение** этого юнита (`subject_unit_id`); все уже запланированные **обнаружения** сдвигаются на более поздний срок, сохраняя относительный порядок.
3. После завершения **всех** действий в рамках этого приказа на timeline ставятся **поворот** к ближайшему из врагов (центр конуса оружия на цель) и **атака** его. Обе вставки — на дорожке **активности**.

**Прерывания (кроме изменения приказа):** любое действие прерывается смертью исполнителя. При потере прямой видимости при обнаружении (луч пересекается другим объектом) или выходе цели из конуса **обнаружение** прерывается. Если ранее обнаруженный юнит пропал из поля зрения — при следующем контакте обнаружение выполняется заново.

### 7.3. Параллельность движения и активности

Между типами (дорожки **движения** и **активности**) действия независимы: очередь и вставки на **активности** (в т.ч. по п. 7.2) не отменяют и не переписывают приказ **перемещение** на дорожке движения, и наоборот.

### 7.4. Физический луч

`PhysicsRayQueryParameters2D`:

- **видимость / обнаружение** — проверка на юнитов противника и правила прямой видимости / конуса;
- **попадание при выстреле** — все юниты (включая союзников), чтобы была возможна **FF** при случайном направлении в конусе.

## 8. Таймлайн UI (timeline_view.tscn)

- `TimelineRuler` — время слева направо, **отметки границ ходов**
- `OrderBlock` — плашка приказа
- `Playhead` — бегунок предпросмотра

**Вертикальное разделение на две зоны** по типам приказов: движение, активность (на дорожке активности — «смотреть», атаки и т.д.).

Плашки, выходящие за предел текущего хода — полупрозрачные.

Предпросмотр на timeline - бегунок.
При перемещении бегунка:
- пересчитываются позиции **юнитов той же команды, что и выбранный** (в прототипе один человек за сторону — фактически все юниты этой стороны) **без коллизий** (допускается наложение);
- направление взгляда интерполируется;
- на редактирование приказов предпросмотр не влияет; в будущем — изменение приказа «с этого момента» (заложить при необходимости в API).

## 9. Управление (main.gd + таймлайн)

### 9.1. Фаза планирования — карта

- левый клик по юниту — выбор юнита
- правый клик по точке — приказ **перемещения** (создание/продолжение с текущего момента на треке движения — по правилам редактора)
- **Ctrl + правый клик** — выбор направления обзора (приказ «смотреть» на дорожке **активности**)
- кнопка «Start Turn» или **пробел** — запуск фазы симуляции

### 9.2. Фаза планирования — timeline при активном юните

- левый клик по плашке приказа — выбор приказа
- левый клик по пустой части timeline — создание нового приказа **с текущего момента**
- «захватить и потянуть» край плашки — изменить длительность
- «захватить и потянуть» плашку — переместить приказ в рамках свободного места (наложение приказов на одной дорожке не допускается)
- **Delete** при выделенном приказе — удалить приказ
- **Ctrl + колёсико** над timeline — масштаб
- колёсико над timeline — перемещение «окна видимости» (скролл, вправо-влево)
- «Start Turn» или пробел — запуск симуляции

### 9.3. Фаза симуляции

Игрок не может повлиять на юнитов; отображается одновременное выполнение выданных на планировании приказов.

## 10. Окружение

- карта: плоскость без препятствий
- границы: непроходимые края (`StaticBody2D` или эквивалент)

## 11. Смерть юнита

Любое действие прерывается смертью выполняющего юнита. Приказы и состояния мёртвого юнита очищаются, юнит удаляется с поля.

Если другой юнит уже начал атаку по цели, которая умерла до выстрела (начал нажимать спуск) то он не прерывает своего действия; при выстреле луч проверяет попадание по оставшимся коллайдерам.
