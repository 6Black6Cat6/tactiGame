# Техническое задание (Godot 4)

Постановка для реализации прототипа; механика согласована с `dd_proto4.md`.

**Приказ** — указание игрока юниту. **Действие** — минимальная единица выполнения на timeline во время симуляции.  
Типы: **движение**, **вращение**, **активность**. Типы выполняются независимо; изменение действия одного типа не прерывает действия других типов.

- `rotate_speed_min` = 60, `rotate_speed_max` = 120 (град/сек)

## 3. Сцена `unit.tscn`

- `Node2D` (корень)
- `Sprite2D`
- `CollisionShape2D` (круг, радиус из конфига)
- скрипт: `unit.gd`

Компоненты юнита: тело, оружие, видимость.

## 4. `unit.gd` — параметры

- `ActionType`: `MOVE`, `ROTATE`, `WATCH`, `DETECTION`, `SHOT` (и др. при необходимости)
- `Track`: `MOVEMENT`, `ROTATION`, `ACTIVITY`

Поля:

- `reaction_time`
- `move_speed`
- `rotate_speed`
- `weapon`
- `position: Vector2`
- `direction: Vector2`
- `team_id: int` (0 — игрок, 1 — противник)
- `timeline`

## 5. Ресурс `order.gd`

### 5.1. Типы приказов

- `MOVE` — перемещение (тип `MOVEMENT`)
- `ROTATE` — повернуться в фиксированное направление (тип `ROTATION`)
- `WATCH` — смотреть на точку (тип `ROTATION`)
- `SHOT` — выстрел в текущем направлении (тип `ACTIVITY`)
- `ATTACK` — атака по возможности (тип `ACTIVITY`)

### 5.2. Общие поля приказа

- `track: Track`
- `start_time: int`
- `duration: int`
- `target: Vector2` — для `MOVE`, `ROTATE` и `WATCH` 

Длительность:

- для приказов со скоростью вычисляется из скорости и расстояния/угла (`MOVE`, `ROTATE`);
- для фиксированных — фиксированная (`SHOT`);
- для невычислимых заранее (`ATTACK`, `WATCH`) — задается игроком на timeline.

### 5.3. Действия симуляции (`action.gd`)

Действия — записи на timeline во время фазы симуляции.

| Тип действия | Трек | Поля | Длительность |
|---|---|---|---|
| `MOVE` | `MOVEMENT` | `target: Vector2` | из расстояния и `move_speed` |
| `ROTATE` | `ROTATION` | `direction: Vector2` | из угла и `rotate_speed` |
| `WATCH` | `ROTATION` | `look_at: Vector2` | пока действует приказ |
| `DETECTION` | `ACTIVITY` | `subject_unit_id: int` | `reaction_time` |
| `SHOT` | `ACTIVITY` | — | ожидание `reaction_time`, затем мгновенный выстрел |

Правила заполнения:

- приказ `MOVE` -> действия `MOVE`;
- приказ `ROTATE` -> действия `ROTATE`;
- приказ `WATCH` -> действия `WATCH`;
- приказ `SHOT` -> действие `SHOT`;
- приказ `ATTACK` -> действия `DETECTION` и `SHOT`, плюс `WATCH` перед `SHOT` по правилам п. 7.2.

Прерываемость действий:

- прерываемы: перемещение, поворот, смотреть, обнаружение;
- не прерываемо: выстрел.

## 6. Модель timeline (`timeline.gd`)

- `orders: Array[Order]` — приказы фазы планирования
- очередь действий (`Array[Action]` или эквивалент) — формируется на фазе симуляции
- `turn_duration: int`
- состояние просмотра/масштаба UI

Дорожки:

- `MOVEMENT`
- `ROTATION`
- `ACTIVITY`

Методы:

- `add_order(order, track, start_time)`
- `resize_order(order, new_duration)`
- `remove_order(order)`
- `get_orders_at_time(time, track)`

## 7. Симулятор (`simulator.gd`)

Вход: список юнитов, их timeline, момент начала хода.

### 7.1. Фазы

- планирование: игрок задает приказы;
- запуск симуляции: вручную (`Start Turn` / пробел);
- во время симуляции управление отключено.

### 7.2. Приказ `SHOT`

1. Ожидание на время реакции (нажатие на спуск).
2. Мгновенный выстрел: случайное направление в конусе разброса; попадание проверяется физическим лучом.

### 7.3. Приказ `ATTACK` (атака по возможности)

При появлении противника в конусе видимости:

1. В пределах этого приказа убрать запланированные `SHOT`.
2. После текущего выполняемого действия добавить `DETECTION`; ранее поставленные `DETECTION` сдвинуть позже.
3. После завершения действий в рамках этого приказа добавить `WATCH` на ближайшего врага и затем `SHOT`.

### 7.4. Параллельность

Дорожки `MOVEMENT`, `ROTATION`, `ACTIVITY` независимы.  
Изменение действий на одной дорожке не прерывает действия на других дорожках.

### 7.5. Прерывания:

- `SHOT` не прерывается после начала, остальные могут прерваны удалением приказа;
- `DETECTION` прерывается потерей прямой видимости или выходом цели из конуса;
- любое действие прерывается смертью выполняющего юнита.

### 7.6. Физический луч

`PhysicsRayQueryParameters2D`:

- для обнаружения: проверка видимости противников;
- для выстрела: попадание по всем юнитам (включая союзников, FF возможен).

## 8. UI timeline (`timeline_view.tscn`)

- `TimelineRuler`
- `OrderBlock`
- `Playhead`

Вертикальное разделение на 3 зоны: движение, вращение, активность.

Плашки за границей текущего хода — полупрозрачные.

Предпросмотр (бегунок):

- пересчет позиций своих юнитов без коллизий;
- интерполяция направления взгляда;
- на редактирование приказов не влияет.

## 9. Управление (`main.gd` + timeline)

### 9.1. На карте (фаза планирования)

- ЛКМ по юниту — выбор юнита
- ПКМ по точке — `MOVE`
- Ctrl + ПКМ — выбор направления обзора `ROTATE`
- Ctrl + Shift + ПКМ — выбор точки цели для слежения `WATCH`
- `Start Turn` или пробел — запуск симуляции

### 9.2. На timeline

- ЛКМ по плашке — выбор
- ЛКМ по пустому месту — создание нового приказа с текущего момента
- перетянуть край — изменить длительность
- перетянуть плашку — переместить в свободное место на дорожке
- Delete — удалить
- Ctrl + колесо — масштаб
- колесо — сдвиг окна времени

### 9.3. Фаза симуляции

Игрок не может влиять на юнитов; выполняются выданные приказы.

## 10. Окружение

- карта: плоскость без препятствий
- границы: непроходимые края

## 11. Смерть юнита

При смерти юнита его действия/состояния очищаются, юнит удаляется с поля.  
Если другой юнит уже начал выстрел по цели, которая умерла, выстрел не прерывается; луч проверяет попадание по оставшимся коллайдерам.
